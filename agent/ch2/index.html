    第 2 章 · 上下文工程¶

    第 2 章 · 上下文工程

    难度 ⭐ 入门 · 一句话：上下文是 Agent 的眼睛——决定能力上限的往往不是模型有多聪明，而是它看得有多清楚。

    💎 核心概念¶

    👀 上下文是眼睛

    同一个「帮我修 bug」，上下文里有没有代码结构、流程规范、环境信息，结果天差地别。决定上限

    ✉️ 消息四角色

    system（开发者的规则）· user（用户输入）· assistant（模型回复）· tool（工具结果）。API 结构

    🧰 tools 字段

    工具定义是请求顶层的独立字段，不占消息角色——告诉模型「你能用这些工具」。独立字段

    ⚡ KV Cache

    模型计算时会缓存中间结果。对话前面部分越稳定，缓存复用越多，跑得越快越便宜。性能

    📝 提示工程

    优化系统提示词：身份、行为规则、约束。上下文工程在「入口」的部分。入门必会

    🎒 Agent Skills

    把专业操作写成文档按需加载，像「背包里装技能书」，用到的才翻开。渐进式披露

    ✂️ 上下文压缩

    对话太长时，把历史总结成摘要、挑出重点，让上下文「轻装上阵」。瘦身

    🖼️ 关键图：上下文窗口里装了什么¶

    图：上下文窗口的构成概览 · 来自原书图 2-1

    你的每一次输入、开发者写的规则、模型自己的回复、工具的返回结果——全都在这个「窗口」里，一次请求一起交给模型。

    🫧 打个比方¶

    🧑‍💼 一位天才工程师新入职

    想象一位理论功底深厚的天才工程师刚加入你的团队。他聪明绝顶，但对你们的产品架构、业务规则、团队规范一无所知——他甚至不知道哪些信息该找谁问。AI Agent 就是这样一位「永远的新员工」：给足背景信息，它能干得很好；什么都不告诉它，再聪明也是白搭。所以「人和模型一样，最重要的是 Context（上下文）」。构建 AI 友好的团队，首先是一场文档化运动。

    📖 关键术语¶

    术语 白话解释
    上下文工程 系统性设计、组织、提供 AI 完成任务所需背景信息的技术
    消息角色 system / user / assistant / tool 四种身份
    系统提示词 开发者写的最高优先级指令，定义身份和规则
    KV Cache 注意力计算的缓存，前缀复用能显著提速降本
    提示词注入 恶意文本混进上下文，诱导模型违规（安全要点）
    Agent Skills 按需加载的专业技能文档
    上下文压缩 总结/摘选历史，控制上下文长度
