    第 10 章 · 多 Agent 协作

    难度 ⭐⭐⭐⭐⭐ 应用 · 一句话：群体的智能可以高于个体——一群专家级 Agent 组织得当，能超过任何一位天才。

    💎 核心概念¶

    🌍 群体智能 > 个体

    人类文明就是明证：单个人智力有限，靠分工、协作、辩论和知识代际累积，社会整体智能远超任何天才。根本意义

    🔗 共享上下文

    后一个 Agent 继承前一个的完整对话历史和轨迹。换角色不丢记忆——像接手的同事连你和客户的聊天记录都看得到。隐式协调

    🧱 不共享上下文

    每个 Agent 独立工作，靠文件、消息、接口交换信息。模块化、隔离好、易扩展。显式协调

    ✉️ 通信三机制

    工具调用参数（结构化传参）· 共享文件系统（读写共同目录）· 消息总线（中转站异步转发）。IPC 范式

    📮 消息总线

    像公司邮件系统：发件不用等对方在线，先存服务器上，对方上线再处理。适合并行协调。异步通信

    ⚠️ 失败模式

    多 Agent 协作也会崩：上下文膨胀、沟通误解、互相推诿、资源竞争——组织不好反而不如单个。别盲目上多Agent

    🖼️ 关键图：共享与不共享上下文¶

    图：共享上下文与不共享上下文对比 · 来自原书图 10-1

    🫧 打个比方¶

    🏢 一个团队，两种开会方式

    共享上下文像一个小团队从头到尾盯一个项目：每个新接手的成员都能翻到全部聊天记录和文档，信息不丢，但资料越堆越多。不共享上下文像大公司的不同部门：每个人在自己工位独立干活，通过共享文档和会议纪要交换信息，不用盯着别人的屏幕——模块清晰，但要靠约定好的接口沟通。还有一句老话值得记住：「不要通过共享内存来通信，而要通过通信来共享内存」。

    📖 关键术语¶

    术语 白话解释
    多 Agent 系统 多个 Agent 协同完成任务
    共享上下文 后任 Agent 继承前任全部历史
    不共享上下文 各自独立，靠显式通信
    消息总线 中转站式异步消息传递
    工具调用参数 结构化数据随调用传给下游
    共享文件系统 Agent 们读写共同目录
    集体智能 群体整体表现超过成员简单相加
