    第 8 章 · Agent 的持续进化¶

    第 8 章 · Agent 的持续进化

    难度 ⭐⭐⭐⭐ 专家 · 一句话：保存经历不等于从经历中学习——让 Agent 从「会完成任务」走向「能可靠工作」。

    💎 核心概念¶

    🎯 保存 ≠ 学习

    把 100 条轨迹存进向量库，不会自动学会跨案例比较——哪些步骤反复出现、哪次成功是碰运气。学习发生在评价、对照、归纳、验证之后。核心区分

    ✅ 三层验证

    结果验证器（办成没有）→ 过程验证器（用允许的方式办的吗）→ 质量验证器（办得合适吗）。越靠下越信代码真值。从下往上

    🧭 四种更新方法

    更新知识（经验文档）· 指令（系统提示词）· 程序（工具和代码）· 参数（训练模型）。载体不同

    🛡️ 先验证再生效

    所有修改先成候选版本，过回归测试和安全检查，才影响下一轮运行。防固化错误

    ⚠️ 为什么不能让模型自己改自己

    生产环境没干净学习信号：用户满意≠合规，测试通过可能删了失败用例；未验证反馈会固化提示注入。工程兜底

    ♻️ 在线 + 离线双循环

    线上跑任务收集轨迹，离线批量学习更新，再发布回去——两条腿走路。架构

    🫧 打个比方¶

    📝 从「会做题」到「越做越熟练」

    Agent 的尴尬在于：能零样本解决从没见过的难题，却可能做了 10000 次相似任务后，第二天还犯第一天的错。就像学生做了一万道题却不订正错题本——做得多不等于学得会。持续进化就是给 Agent 配一个「错题本 + 订正系统」：记录每次做题的证据，验证对错，归纳规律，然后更新自己的知识、规则、工具甚至参数。

    📖 关键术语¶

    术语 白话解释
    持续进化 Agent 从自身运行经验中学习的能力
    三层轨迹验证 结果 / 过程 / 质量 逐层把关
    Rubric 预先定义好的评分量表
    经验知识文档 从评价过的轨迹提炼出的经验
    回归测试 改完确认没把旧能力改坏
    双循环 在线执行收集 + 离线学习更新
