    第 3 章 · 用户记忆与知识库

    难度 ⭐⭐ 进阶 · 一句话：上一章解决「单次对话」的上下文，这一章解决「对话结束后」还要记住用户、记住知识。

    💎 核心概念¶

    👤 用户记忆

    针对单个用户的个性化记忆：偏好、习惯、需求。个体尺度——让 Agent「懂你」。

    📚 知识库

    面向所有用户共享的知识：法规、流程、领域文档。群体尺度——让 Agent「是专家」。

    🧠 记忆三特征

    选择性（只留有用的）· 抽象化（提炼成通用偏好）· 结构化（好检索）。提取原则

    🔍 RAG

    检索增强生成：先到文档里搜出相关内容，再把结果喂给模型生成回答。知识管道

    🧬 向量检索

    把文本变成数学向量，按「语义相似度」找最相关的内容——搜的是意思，不是关键词。底层技术

    🕸️ 知识图谱

    把知识建成「实体 + 关系」的网，比如 GraphRAG——回答跨实体的问题更强。进阶

    🖼️ 关键图：RAG 是怎么工作的¶

    图：RAG 查询流程——检索、增强、生成 · 来自原书图 3-5

    提问时，先把问题拿到知识库里搜出相关片段，连同问题一起交给模型——模型不用硬背整个知识库，也能答得准。

    🫧 打个比方¶

    🤝 记住朋友，而不是记住每句话

    你和一个朋友相处，不会记得每次对话的原文，而是在心里逐渐形成一个关于他的「生动模型」——他爱坐靠窗位、吃素、爱用哪个会员号。下次订票，你不用再问，因为他已经「懂你」了。用户记忆就是这个道理：Agent 把散落在冗长对话里的关键信息提取、压缩、存下来，而不是囫囵吞下每一句话。

    📖 关键术语¶

    术语 白话解释
    用户记忆 Agent 对单个用户的持久化个性化知识
    知识库 所有用户共享的领域知识集合
    RAG 检索增强生成，先检索再生成
    向量检索 / Embedding 把文本变成向量，按语义相似度检索
    重排序 (Rerank) 检索结果太粗时，再精细排一遍序
    知识图谱 实体与关系组成的知识网络
    GraphRAG 基于知识图谱的 RAG 变体
